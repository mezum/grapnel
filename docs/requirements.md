# grapnel 要件定義書

キーボード・マウス・ゲームパッドの入力を別の入力へ変換する Windows 用常駐ツール。

## 1. 対象環境

| 項目 | 内容 |
| --- | --- |
| OS | Windows 11 22H2 以降 (x64) |
| 言語 | Rust stable, edition 2024 |
| 権限 | 通常権限で動作する。管理者として起動すれば昇格したアプリにも作用する (任意) |
| 外部ドライバ | 不要 |

## 2. 構成

| 成果物 | 役割 |
| --- | --- |
| `grapnel.exe` (常駐) | 入力を変換する。タスクトレイに常駐し、メインウインドウは持たない |
| `grapnel-settings.exe` (設定ツール) | Tauri 2 + Leptos 製の GUI。設定を読み込み、フォームで編集して保存する |

- 共通のロジックは小さな crate に分け、単体のライブラリとして再利用できるようにする。
- 常駐側のログ:
  - デバッグビルドでは標準出力に出す (コンソールサブシステム)。
  - リリースビルドではコンソールを出さない。致命的なエラー (起動できない設定など) は MsgBox で、実行中のエラーは画面左下のトーストで知らせる。どちらも `%LOCALAPPDATA%\grapnel\grapnel.log` に記録する。

## 3. 機能要件

### 3.1 入力の取得

- R-IN-1: キーボードとマウスの入力を低レベルフック (`WH_KEYBOARD_LL` / `WH_MOUSE_LL`) で取得し、握りつぶせる。
  - どのデバイスから来た入力かは区別しない。
- R-IN-2: マウスはボタン (左/右/中/X1/X2)、ホイール (上下左右)、ジェスチャー (ボタンを押しながら動かした方向の列) を入力として扱える。
- R-IN-3: ゲームパッドの入力を gilrs で取得する。ボタン、十字キー、スティックとトリガー (しきい値でボタン扱い) を入力として扱える。
  - ゲームパッドの元の入力は他のアプリから隠せない (ドライバが必要なため対象外)。
- R-IN-4: 自分が注入した入力は変換の対象にしない。

### 3.2 設定

- R-CF-1: 設定は TOML で宣言的に書く。
- R-CF-2: エントリファイル (既定は `%APPDATA%\grapnel\config.toml`、起動引数で変更可) から `include` (glob 可) で複数のファイルを読み込める。
- R-CF-3: ホットリロードはしない。トレイメニューまたは設定ツールの「保存して適用」で再読み込みする。
- R-CF-4: 設定に誤りがあれば、ファイル名と箇所の分かるエラーを出す。再読み込みに失敗したときは直前の設定で動き続ける。

### 3.3 入力ルール

- R-RU-1: Emacs 風の chord の連続 (`C-x t 0`, `M-x` など) を入力として定義できる。
- R-RU-2: chord の途中で定義外の入力が来たときと、時間切れのときの扱い (流す / 捨てる / フォールバックを送る) と時間切れまでの時間をルールごとに指定できる。既定は「流す」「時間切れなし」。
- R-RU-3: Vim 風のモードを定義でき、ルールごとに有効なモードを指定できる。モードはグローバルに 1 つで、アクションで切り替える。モードごとに、定義されていない入力を握りつぶすかどうかを指定できる。
- R-RU-4: ユーザー定義の修飾キーを追加できる。単独でタップすれば指定したキーを送り、押したまま別の入力をすれば修飾キーとして働く (tap/hold 兼用)。
- R-RU-5: キーボード・マウス・ゲームパッドの入力を組み合わせたルールを書ける (例: `Mu-LButton`, `C-x WheelUp`)。
- R-RU-6: 入力を押している間、出力を押したままにする (`hold`、既定) か、すぐに離す (`tap`) かをルールごとに指定できる。
- R-RU-7: ルールは実行するアクションを名前で指定する。
- R-RU-8: アクションに今の状況で使える実装が無いときに送るフォールバックの入力を指定できる。既定は元の入力をそのまま送る。
- R-RU-9: ルールが働く条件をターゲット (複数可、どれかに合えばよい) で指定できる。省略すれば無条件。

### 3.4 ターゲット

- R-TG-1: ターゲットは名前付きの条件で、次の項目を組み合わせる (すべて満たせば合う)。
  - アプリ名 (exe のファイル名、またはフルパス)
  - ウインドウのタイトル
  - ウインドウのクラス名
  - フォーカスのあるコントロールのクラス名
  - UI Automation の AutomationId / Name / ControlType
- R-TG-2: `not` / `any` / `all` で他のターゲットを組み合わせられる。
- R-TG-3: 文字列は、大文字小文字を区別しない完全一致、`glob:` 接頭辞で glob、`re:` 接頭辞で正規表現として照合する。

### 3.5 アクション

- R-AC-1: 同じ名前のアクションに複数の実装を持たせ、それぞれに適用条件 (ターゲット、複数可) を付けられる。上から順に評価し、最初に合った実装を使う。
- R-AC-2: 実装は次の手順を順に実行する (複数可)。
  - キー入力 (chord の連続)
  - 文字入力 (Unicode)
  - マウス入力 (ボタン、ホイール、相対/絶対移動)
  - 待機
  - プログラムの起動
  - 他のアクションの呼び出し (引数付き)
  - モードの切り替え
  - 常駐側への指示 (一時停止の切り替え、再読み込み、終了)
  - 入力欄の表示 (確定すると、入力した文字列を引数として別のアクションを呼ぶ)
- R-AC-3: 引数は `{arg}` で文字入力・プログラムの引数・呼び出しの引数に埋め込める。
- R-AC-4: ゲームパッドへの出力は今回の対象外とし、後から手順の種類として追加できるようにしておく。

### 3.6 一時停止とパススルー

- R-PS-1: 指定したターゲットに合うアプリが前面にある間は、キーボード・マウスのフックとゲームパッドの読み取りを外す。前面から外れたら元に戻す。
  - この間も前面ウインドウの監視と、一時停止切り替えのホットキー (`RegisterHotKey`) は残す。
- R-PS-2: トレイメニューとホットキーで、変換全体を一時停止/再開できる。

### 3.7 トレイ

- R-TR-1: トレイアイコンのツールチップに現在のモードと一時停止の状態を出す。
- R-TR-2: メニュー: 一時停止/再開、設定を再読み込み、設定ツールを開く、終了。

### 3.8 設定ツール

- R-GU-1: エントリファイルとそこから include されるファイルを読み込み、ファイルごとにフォームで編集できる。
- R-GU-2: 保存前に検証し、エラーがあれば保存しない。
- R-GU-3: 「保存して適用」で保存したうえで、名前付きパイプ経由で常駐側に再読み込みを指示する。
- R-GU-4: キー欄はその場で書式を検証する。
- 保存するとファイル内のコメントは消える (フォーム編集のみのため許容する)。

## 4. 非機能要件

- R-NF-1: フックの処理は短時間で終える (目安 1 ms 未満)。待機、入力欄、プログラム起動でフックを止めない。
- R-NF-2: 変換エンジンは OS に依存しない純粋なロジックとし、単体テストで検証する (TDD)。
- R-NF-3: 例外的な状態 (押しっぱなしのまま一時停止した等) でも、キーが押されたままにならないよう解放する。

## 5. 対象外 (今回は作らない)

- デバイスごとの区別、ゲームパッドへの出力、設定のホットリロード
- 設定ツールでの TOML 直接編集と前面ウインドウ情報の取得
