# Notes for agents

grapnel remaps keyboard, mouse and gamepad input on Windows 11. `README.md` covers building and
using it; `docs/` holds the requirements, the config specification and the design (all in Japanese).
This file is what those documents do not say.

## Commands

- `just lint` — `cargo fmt --check` plus clippy (`-D warnings`) for the workspace and the wasm UI.
- `just test` — the whole `cargo test`. Run it whole: `examples_are_in_saved_form` compares the
  bundled `examples/*.toml` against what the settings tool would write, and it spans crates.
  `GRAPNEL_BLESS=1 cargo test -p grapnel-config examples_are_in_saved_form` rewrites them.
- `just build` — release build of both exes. `just restart` = stop, build the settings tool, run.
- CI (`.github/workflows/ci.yml`) runs `just lint`, `just test` and `just settings`.

grapnel is usually running on the maintainer's machine, so a release build cannot overwrite
`target/release/grapnel.exe`. Use `just stop` first, or build elsewhere with
`cargo build --target-dir target/verify`.

`apps/settings/dist` is generated and not committed, so `cargo clippy -p grapnel-settings` (the Tauri
back end) only works after `just settings`. That is why `just lint` leaves it out.

## Layout

`crates/grapnel-{keys,schema,config,engine,pad,win}` and `apps/{grapnel,settings}`.

- `grapnel-engine` is platform-free: events in, commands out, time passed in as milliseconds. Keep
  Win32 out of it — that belongs in `grapnel-win`.
- `grapnel-schema` mirrors one TOML file 1:1; `grapnel-config` validates and compiles it.
- `apps/settings` is a Tauri 2 back end plus a Leptos (wasm) front end. Native menus are built in the
  back end (`set_menu`), because the front end cannot.

## Things that bit us

- **Key names follow a layout.** Symbols resolve against `settings.layout` (jis, us, uk, de, fr).
  The tables in `crates/grapnel-keys/src/layouts.rs` are generated by `gen-layouts.ps1` from the
  layouts Windows ships; regenerate rather than hand-editing.
- **A call passes only the argument it names.** `{ call = "x" }` and the `"x"` shorthand pass an
  empty argument; `arg = "{arg}"` passes the current one. Nothing is inherited implicitly.
- **`Sleep` stops planning.** The steps after it come back as `Command::Resume`, which
  `Engine::resume` plans once the sleep is over, so modifier state is current. Each sleep waits on
  its own thread and carries the executor generation, so a reload or suspend drops it.
- **Hooks are never reinstalled automatically.** Windows drops a low-level hook without notice when a
  callback exceeds `LowLevelHooksTimeout`; recovery is the tray menu's "Reinstall the input hooks".
  Deliberate — do not add a watchdog.
- **UI Automation answers can be stale.** Each refresh is numbered and a result is used only if it
  answers the newest one.
- A zero relative mouse move never reaches the low-level hook; an absolute move to the current
  cursor position does.

## Conventions

- Code and comments in English. Documents under `docs/`, and text the user sees, in Japanese, with
  English in `locales/en.toml`.
- Every locale file carries the same keys (`apps/grapnel/tests/locales.rs` checks it). Config errors
  are `Problem { file, at, on_key, msg: Msg }`; the settings UI's `Place` paths must match the `at`
  spelling in `compile.rs`, or errors will not attach to fields.
- Use wording the maintainer gives verbatim; translating it into other locales is fine.

## Working on this repository

- Small, reviewable commits: about 250 changed lines at most.
- Run `codex review --uncommitted < /dev/null` before pushing. The stdin redirect matters; without it
  codex waits for input forever.
- After finishing a change, run `just restart` in the background so it can be tried right away.
- One PR per issue where the work allows it, and say in the PR what was only checked by tests rather
  than by running it.
- Never name a branch `dependabot`: it blocks Dependabot's own `dependabot/...` branches.
- `gh` runs as the repository owner, so comments an agent posts appear under their name. End them
  with a line saying they come from the agent.
- Workflows: prefer actions from `actions/*`, and pin third-party actions to a commit SHA.
- To release: raise `workspace.package.version`, then push a `vX.Y.Z` tag. The release workflow
  checks the tag against that version, builds and publishes the zip.
